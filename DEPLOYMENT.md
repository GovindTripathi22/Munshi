# Munshi Production Deployment & Operations Guide

## 1. Architecture & Persistence Strategy

Munshi runs an autonomous multi-agent accounting engine backed by a persistent **SQLite double-entry general ledger** and **SHA-256 tamper-evident cryptographic audit trail**.

```
[Client / UI / MCP] 
       │
       ▼
 [FastAPI REST API / CLI] ─── (Human Auth Gate u/s 50k)
       │
       ▼
 [LangGraph Orchestrator] 
 ┌─────┼─────────────────────────┐
 │     │                         │
 ▼     ▼                         ▼
[Bookkeeper] [GST Engine] [Reconciliation]
       │
       ▼
[SQLite Ledger Engine (WAL Mode + Mutex)]
 ├── data/munshi.db (Accounts, Journal Entries, Audit Records)
 └── SHA-256 Cryptographic Hash Chain
```

> [!IMPORTANT]
> **Single-Instance Deployment Limit**: Because the general ledger persists to a local SQLite database with WAL mode and transaction-level file locking, run **one container instance** per business entity.

## 2. Security Checklist

- [x] **Non-Root Execution**: Container runs as unprivileged user `munshiuser` (UID `10001`).
- [x] **API Key Authentication**: Configure `MUNSHI_API_KEY` in production. Unauthenticated requests to `/v1/workflows/*` return HTTP 401.
- [x] **Strict Human-in-the-Loop (HITL) Separation**:
  - AI subagents over MCP (Model Context Protocol) and chat can record and inspect transactions, but **cannot approve** vouchers.
  - Vouchers exceeding ₹50,000 can only be approved by authenticated human operators via CLI (`/approve`) or REST API (`POST /v1/workflows/{thread_id}/hitl`).
  - Already `POSTED` or `REJECTED` vouchers are immutable.
- [x] **Tamper Detection**: Run `python -m munshi.cli verify` or monitor `GET /health`. If any database rows are modified outside the audit trail, `/health` responds with HTTP 500 and fails container health probes.
- [x] **Privacy Guardrails**: Optional Gemini account-code classification helper receives **only the transaction narration text**, never financial amounts, invoice dates, or bank balances.

## 3. Database Backup & Disaster Recovery

### Online Backup Procedure
Because SQLite runs in WAL mode, you can safely take hot backups while the service is actively processing transactions:

```bash
# Hot snapshot using SQLite backup command
sqlite3 data/munshi.db ".backup data/backup_$(date +%Y%m%d_%H%M%S).db"
```

### Automated Backup Cron Job (Daily at 02:00 AM)
```bash
0 2 * * * cd /opt/munshi && sqlite3 data/munshi.db ".backup backups/munshi_$(date +\%F).db" && find backups/ -mtime +30 -delete
```

### Restore Procedure
1. Stop the Munshi service:
   ```bash
   docker compose down
   ```
2. Replace `data/munshi.db` with your verified snapshot:
   ```bash
   cp backups/munshi_2026-10-23.db data/munshi.db
   ```
3. Run forensic integrity verification before starting service:
   ```bash
   python -m munshi.cli verify
   ```
4. Restart service:
   ```bash
   docker compose up -d
   ```

## 4. Statutory GST Compliance Notice

- **Post-September 22, 2025 Slabs**: In accordance with statutory GST rationalization, 12% and 28% tax slabs are discontinued for transactions dated after September 22, 2025. Vouchers referencing 12% or 28% post-reform are automatically rejected.
- **Section 49 & 49A Set-Off Rules**: IGST credit is consumed first across IGST, CGST, and SGST liabilities; cross-utilization between CGST and SGST is strictly disallowed.
- **Section 17(5) Blocked ITC**: Expenses on catering, restaurants, motor vehicles, and club memberships are automatically capitalized into expense accounts without claiming Input Tax Credit.
- **Statutory Filing**: All GST return summaries (GSTR-1, GSTR-3B) generated by Munshi should be reviewed by a qualified Chartered Accountant (CA) before submission to the GSTN portal.

## 5. Docker Deployment

### Start Container
```bash
docker compose up -d --build
```

### Verify Container Health
```bash
curl -f http://localhost:8000/health
```

### Run CLI Tools Inside Container
```bash
# Forensic Verification
docker exec -it munshi-os python -m munshi.cli verify

# Interactive Chat Assistant
docker exec -it munshi-os python -m munshi.cli chat

# Full Forensic Benchmark
docker exec -it munshi-os python -m munshi.cli benchmark
```
